# Atlas backend: Java API + Python pipeline over gRPC

```text
React (later) ──HTTPS/REST──▶ Java Spring Boot (atlas/) ──gRPC──▶ Python pipeline (app/) ──▶ PostgreSQL, SQLite, DiskANN, model
```

- **Java (`atlas/`)** is the public API and the security boundary: accounts, passwords,
  JWTs, request validation, uploads, and translating pipeline errors into HTTP.
- **Python (`app/`)** keeps all the intelligence: decomposition, memory, retrieval and KSV,
  thinking, generation, ingestion and its storage quota. `main.py serve` exposes it over gRPC
  through the same `AtlasPipeline` the CLI uses.
- **The contract** is `proto/atlas/v1/atlas_service.proto`. Java generates its bindings at
  build time. Python's are generated by `app/scripts/generate_grpc.py` and checked in, and a
  test fails if they drift from the `.proto`.

## Running it locally

Prerequisites: Java 21, Python via `uv` (see `app/CLAUDE.md`), the model in
`app/models/draft_model/`, and PostgreSQL with pgvector holding the database named in
`app/.env`.

```bash
# Once per shell: two shared secrets (never commit them)
export ATLAS_JWT_SECRET="$(openssl rand -base64 48)"        # Java only
export ATLAS_GRPC_SERVICE_TOKEN="$(openssl rand -hex 32)"   # both sides, same value

# 1. Python pipeline (loads the model, embedder, reranker and index first)
cd app
uv run --no-sync python main.py serve              # add --no-acquire for no web fetches

# 2. Java API (another shell, same two variables)
cd atlas
./mvnw spring-boot:run                              # or: ./mvnw package && java -jar target/atlas-*.jar
```

Use `uv run --no-sync`: a plain `uv sync` removes llama-cpp-python (bug 9.9).

Java reads `app/.env` for the `DB_*` settings, so both services use the same PostgreSQL.
On first start Flyway creates `user_table`. It records its history in
`atlas_flyway_history`, baselines a database that already holds the Python tables, and
never runs `clean`.

## Configuration

### Java (environment variables; defaults in `atlas/src/main/resources/application.properties`)

| Variable | Default | Purpose |
|---|---|---|
| `ATLAS_JWT_SECRET` | **required** | base64, at least 32 bytes; startup fails without it |
| `ATLAS_JWT_ISSUER` / `ATLAS_JWT_AUDIENCE` | `atlas` / `atlas-api` | checked on every token |
| `ATLAS_JWT_EXPIRATION` | `PT1H` | ISO-8601 duration; returned as `expiresIn` |
| `ATLAS_GRPC_SERVICE_TOKEN` | **required** | at least 16 chars, the same value as Python's |
| `ATLAS_GRPC_HOST` / `ATLAS_GRPC_PORT` | `127.0.0.1` / `50051` | where the pipeline listens |
| `ATLAS_GRPC_QUERY_DEADLINE` / `ATLAS_GRPC_INGEST_DEADLINE` | `PT20M` / `PT30M` | per-call deadlines |
| `ATLAS_GRPC_TLS_ENABLED`, `_TLS_TRUST_CERT`, `_TLS_CLIENT_CERT`, `_TLS_CLIENT_KEY` | off | TLS, and mTLS when a client cert is given |
| `ATLAS_HTTP_PORT` | `8080` | HTTP port |
| `ATLAS_ALLOWED_ORIGINS` | `http://localhost:5173,http://localhost:3000` | CORS; `*` is ignored |
| `ATLAS_DB_URL`, `ATLAS_DB_USER`, `ATLAS_DB_PASSWORD` | from `DB_*` in `app/.env` | PostgreSQL |
| `ATLAS_ENV_FILE` | `../app/.env` | where the `DB_*` settings are read from |
| `ATLAS_ARGON2_MEMORY_KIB`, `_ITERATIONS`, `_PARALLELISM`, `_MAX_CONCURRENT` | `65536`, `3`, `1`, `4` | Argon2id work factor |

Upload limits are `atlas.upload.*` and `spring.servlet.multipart.*`: 10 files, 25 MB each,
100 MB per request. Login rate limits are `atlas.rate-limit.*`: 20 attempts per minute per
address, 10 per 15 minutes per email, and 10 registrations per hour per address.

## REST API

Every response carries `X-Request-Id`. Send one (8-64 of `[A-Za-z0-9._-]`) to correlate
requests, or let the server make one; Java and Python both log it. Every error has this shape:

```json
{"timestamp": "...", "status": 404, "error": "Not Found", "code": "CONVERSATION_NOT_FOUND",
 "message": "No such conversation.", "path": "/query", "requestId": "...", "details": {}}
```

### `POST /register` (public)

```json
{"username": "developer", "email": "developer@example.com", "password": "example-password"}
```

- **username:** 3–32 characters from letters, digits, `.`, `_` and `-`, starting with a
  letter or digit. Unique, ignoring case.
- **email:** a valid address, at most 254 characters. Stored trimmed and lower-case, and
  unique.
- **password:** 8–128 characters, kept exactly as typed.

| Status | Meaning |
|---|---|
| `201` | `{"userId", "username", "email", "createdAt"}` |
| `400` | `VALIDATION_FAILED`, with `details` naming each bad field |
| `409` | `USERNAME_TAKEN` or `EMAIL_TAKEN` |
| `429` | rate limited, with `Retry-After` |

### `POST /login` (public)

```json
{"email": "developer@example.com", "password": "example-password"}
```

| Status | Meaning |
|---|---|
| `200` | `{"accessToken", "tokenType": "Bearer", "expiresIn": 3600}`, sent with `Cache-Control: no-store` |
| `401` | `INVALID_CREDENTIALS`: the same answer and the same cost whether the email exists or not |
| `429` | rate limited |

### `POST /query` (Bearer token)

```json
{"conversationId": null, "query": "Explain how PostgreSQL MVCC works."}
```

The user is the token's subject; any user field in the body is ignored. Leave out
`conversationId` to start a conversation. A conversation that belongs to someone else, or
doesn't exist, is `404`.

```json
{"requestId": "...", "conversationId": "...", "conversationName": "PostgreSQL MVCC",
 "newConversation": true, "answer": "...", "status": "COMPLETED", "executionTimeMs": 1250,
 "retryCount": 0, "warnings": [], "persisted": true}
```

- `status` is `COMPLETED`, or `COMPLETED_WITH_WARNINGS` when, for example, memory could not
  be saved; the reasons are listed in `warnings`.
- Errors:
  - `400`: invalid query.
  - `401`: missing, invalid or expired token, or a deactivated account.
  - `404`: `CONVERSATION_NOT_FOUND`.
  - `503`: `BACKEND_UNAVAILABLE` (pipeline down, or a model or database failure), or
    `BACKEND_BUSY` (the queue is full; sent with `Retry-After`).
  - `504`: `BACKEND_TIMEOUT`.
  - `500`: anything else.

The call is synchronous. On a CPU a query takes minutes, so HTTP clients need a long read
timeout.

### `POST /ingest` (Bearer token, `multipart/form-data`, one or more `files` parts)

Accepted types are `pdf docx pptx xlsx txt md html htm json csv`, checked by content as well
as extension. Office files are counted as they decompress (200 MB total, a compression-ratio
limit, an entry limit). Each file is judged on its own. Uploads are private: only the
uploader's queries can retrieve them. The existing ingestion quota applies.

```json
{"requestId": "...", "status": "PARTIAL", "succeeded": 1, "failed": 1,
 "storageUsedBytes": 123456, "storageLimitBytes": 1073741824, "executionTimeMs": 900,
 "files": [
   {"index": 0, "filename": "notes.md", "status": "INGESTED", "documentId": "...", "chunks": 4, "vectors": 4, "storedBytes": 8192},
   {"index": 1, "filename": "tool.exe", "status": "REJECTED", "errorCode": "UNSUPPORTED_TYPE", "message": "'.exe' files are not accepted."}]}
```

A file's status is one of:

- `INGESTED`
- `REJECTED`: it failed validation.
- `FAILED`: the pipeline could not read it, for example `NO_TEXT` or `MALFORMED`.
- `NOT_INGESTED`: a limit stopped the run, for example `QUOTA_EXCEEDED` or
  `VECTOR_STORE_UNAVAILABLE`.

The body above comes back with every one of these statuses:

| Status | Meaning |
|---|---|
| `200` | every file ingested |
| `207` | some files ingested |
| `507` | quota exhausted |
| `413` | every file too large, or the request over the request limit |
| `415` | every file an unsupported type |
| `422` | otherwise, nothing could be ingested |

The request itself can also fail: `400` for no files or more than 10, `401`, or the same
`503` and `504` as `/query`.

### `GET /actuator/health` (public)

`{"status": "UP"}`, with no details. It reports the Java service only.

### `qResponse`

There is no `/qResponse` route. `QResponseHandler` is an internal service that checks
Python's gRPC `QueryResponse` (matching request id, a non-empty answer, a known status) and
builds the REST body. Because it has no route, nothing outside the process can post an
answer into it.

## Security model

- **Passwords:** Argon2id (BouncyCastle via Spring Security) with a random 16-byte salt per
  password. Hashes are stored in the standard encoded form, which carries the parameters
  and salt. Verification uses the encoder, never a string comparison. Hashes made with
  older parameters are rehashed at the next successful login. At most 4 hashes run at once.
  The cost was measured on the development machine: 21 ms at the OWASP minimum
  (19 MiB, t=2), and about 110 ms at the chosen 64 MiB, t=3.
- **Tokens:** HS256 tokens with claims `sub` (the user UUID), `iss`, `aud`, `iat`, `nbf`,
  `exp` and `jti`. Signature, expiry, issuer, audience and a UUID subject are all checked.
  Sessions are stateless and CSRF protection is off, because tokens travel in a header,
  not a cookie.
- **Java to Python:** a shared service token is sent as `authorization` metadata and
  compared in constant time. Python trusts `user_id` only because the caller proved it is
  the Java service, and Java takes `user_id` only from a verified JWT. The connection is
  loopback plaintext by default; TLS or mTLS is configurable on both sides, and Python
  refuses to bind publicly without TLS.
- **Isolation:**
  - A conversation answers only to its owner (the Python registry is the one authority).
  - Memory routing considers only the caller's projects (`project_table.user_id`).
    Existing projects are backfilled at startup; a project shared by several users is left
    ownerless and routable by nobody.
  - Uploads are recorded in `document_owners`, and retrieval keeps only public or
    caller-owned passages.
  - KV-cache checkpoints are keyed by conversation and user.
- **HTTPS:** terminate TLS at a reverse proxy, or set `server.ssl.*`. The API itself
  listens on plain HTTP.

## Behaviour under load and failure

- The pipeline runs one operation at a time, query or ingestion, because the model, index
  and ingestion lock are single-occupancy. Up to `ATLAS_GRPC_MAX_WAITING` requests can
  queue; beyond that the answer is `BUSY` (HTTP 503 with `Retry-After`).
- A queued request whose caller has gone away, or whose deadline has passed, never starts.
  A request that has started runs to completion even if the caller leaves, because a model
  call cannot be interrupted midway and its writes must stay consistent.
- No call is retried automatically, since a query or ingestion may already have committed
  state.
- On shutdown, Python gives in-flight calls 30 seconds and Java drains its channel for 10.
