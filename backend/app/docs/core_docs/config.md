# Configuration & Logging Module (`config.py`)

## Overview & Purpose
The `config.py` module defines centralized configuration parameters and standardized logging utilities across the entire backend application. It ensures that system paths, database locations, vector dimensions, DiskANN tuning parameters, and log formatting are uniformly managed from a single location.

---

## Classes & Public APIs

### `class Config`
A static namespace container that defines defaults and global settings used by the data layer, ingestion pipeline, vector database, and conversational memory modules.

#### Attributes & Parameters
| Attribute | Type | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `APP_NAME` | `str` | `"Final Year Project Backend"` | Human-readable application title. |
| `DATASET_PATH` | `Path` | `Path("dataset").resolve().parent / "dataset"` | Absolute path to the raw dataset directory. |
| `DEBUG` | `bool` | `False` | Controls diagnostic execution modes and logging verbosity (`DEBUG` vs `INFO`). |
| `LOG_FILE` | `str` | `"log/app.log"` | Relative or absolute path where application log files are written. |
| `ABS_PATH` | `str` | *Computed parent path* | Absolute path to the root application directory (`backend/app`). |
| `DATA_DIR` | `str` | `os.path.join(ABS_PATH, "data")` | Directory where intermediate data files are persisted. |
| `DB_PATH` | `str` | `"hierarchical_db"` | SQLite database filename/path used by hierarchical chunking storage. |
| `EMBEDDING_MODEL` | `str` | `"sentence-transformers/all-MiniLM-L6-v2"` | HuggingFace model identifier for generating dense vector embeddings. |
| `MODEL_PATH` | `Optional[str]` | `None` | Path to a local fine-tuned embedding model checkpoint if used. |
| `INDEX_PATH` | `str` | `os.path.join(DATA_DIR, "disk_ann_index")` | Where built index generations live: `gen-NNNNNN/` directories and the `CURRENT` file naming the one in use. Read when used, so tests redirect it. |

| `VECTOR_DTYPE` | `type` | `np.float32` | NumPy data type for vector elements stored in indexes and databases. |
| `EMBEDDING_DIMENSIONS` | `int` | `128` | Dimensionality of dense vector embeddings generated by the embedding model. |
| `VECTOR_DIMENSIONS` | `int` | `128` | Second name for the same width, read by the pgvector table definition. |
| `MAX_VECTORS` | `int` | `1,000,000` | The corpus size the index is designed for. Labels are allocated sequentially, so it uses 0.02% of the `uint32` label space. No index is sized to it any more: the dynamic index reserves every slot up front, 1.2 GB at this size (bug 5.23). |

| `VECTOR_INDEX_RAM_MB` | `int` | `512` | The most RAM the vector index plans to hold, whatever the corpus. Below it a build makes a memory index; past it a disk index, whose node cache takes what is left. |
| `RECENT_VECTOR_CAPACITY` | `int` | `20_000` | Slots in the in-memory index of vectors ingested since the last build — about 34 MB, allocated up front. |
| `INDEX_REBUILD_AT` | `int` | `10_000` | Vectors waiting outside the built index before ingestion builds a new one. Half the recent capacity, so one failed build still leaves room. |
| `MEMORY_HEADROOM_MB` | `int` | `256` | Free memory no index allocation may plan away from the rest of the system. |
| `COMPLEXITY` | `int` | `100` | Search beam width/complexity parameter during index construction and lookups (`L` parameter). |
| `GRAPH_DEGREE` | `int` | `120` | Graph out-degree parameter (`R` parameter) for the DiskANN Vamana graph. |
| `NUM_THREADS` | `int` | `4` | Worker threads allocated for parallel graph indexing and search queries. |
| `K_NEIGHBORS` | `int` | `9` | Default number of nearest neighbor results (`k`) returned during similarity search. |
| `VECTOR_ID_MASK` | `int` | `(1 << 63) - 1` | Masks hash-derived vector ids into the non-negative signed 64-bit range both storage backends accept. |
| `CONVERSATION` | `Path` | *under `DATA_DIR`* | Root of the conversation store. |
| `PROJECT` | `Path` | *under `DATA_DIR`* | Root of the project pool. |
| `MAIN_MODEL_CONTEXT_WINDOW_TURNS` | `int` | `100` | Conversation turns the summariser feeds the draft model in one window. Measured in turns, not tokens. |
| `SNAPSHOT_EVERY_N_TURNS` | `int` | `20` | Unsummarised turns that must accumulate before `ConversationPoolManager` snapshots on its own. |

## Logging

`config.py` no longer implements logging. It re-exports `get_logger`,
`configure_logging`, `log_context`, `log_timing` and `new_correlation_id` from
`logging_setup.py`, so `from config import get_logger` keeps working unchanged
while the implementation lives in one place.

The implementation cannot live here: `logging_setup` must not import `config`,
or a module importing `config` in order to log would close an import cycle. The
dependency runs one way only, `config -> logging_setup`.

`Config.LOG_FILE` and `Config.DEBUG` are still the defaults `main.py` passes to
`configure_logging()`; they are no longer read at logger-creation time.

See **[Logging (`logging_setup.py`)](logging.md)** for the full contract —
handler placement, levels, correlation context, timing, JSON output and the
conventions the tests enforce.
